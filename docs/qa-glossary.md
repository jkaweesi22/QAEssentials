# QA Glossary

## A

- Acceptance Criteria: Conditions a feature must meet to be accepted by stakeholders
- Accessibility: Ensuring software is usable by people with disabilities
- Automation Testing: Using scripts or tools to execute tests automatically
- API Testing: Validating application programming interfaces for correctness and reliability

## B

- Boundary Value Analysis: Testing values at the edge of input ranges
- Build Verification: Quick checks that a build is testable
- Bug: Informal term for a defect in software

## C

- Coverage: How much of a system is tested against requirements or code
- Critical Path: The most important user flow that must always work
- CI/CD: Continuous integration and continuous delivery or deployment
- Compatibility Testing: Ensuring software works across devices, browsers, or platforms

## D

- Defect: A deviation from expected behavior
- Defect Leakage: Defects found after release
- Defect Density: Number of defects relative to system size or complexity
- Defect Life Cycle: Stages a defect passes through from discovery to closure

## E

- Entry Criteria: Conditions required to start a test phase
- Exit Criteria: Conditions required to complete a test phase
- End-to-End Testing: Validating complete user journeys across systems
- Exploratory Testing: Learning-driven testing without predefined scripts

## F

- Functional Testing: Validating features against requirements
- Fail Fast: Identifying issues early to reduce downstream impact

## I

- Integration Testing: Verifying interactions between components
- Impact Analysis: Assessing the potential effect of a change
- Incident: A production issue affecting users

## M

- MTTD (Mean Time to Detect): Average time to identify a defect or issue
- MTTR (Mean Time to Resolve): Average time to fix a defect or issue
- Manual Testing: Tests executed by a human without automation

## N

- Non-Functional Testing: Testing quality attributes such as performance and security

## P

- Performance Testing: Evaluating speed, scalability, and stability
- Production Monitoring: Observing system behavior after release
- Priority: Importance of fixing a defect relative to others

## R

- Regression Testing: Re-testing to ensure changes did not break existing behavior
- Risk-Based Testing: Prioritizing tests based on impact and likelihood
- Root Cause Analysis (RCA): Identifying the underlying cause of defects

## S

- Sanity Testing: Focused validation of a small change
- Smoke Testing: Broad, shallow checks for basic stability
- STLC: Software testing life cycle
- Severity: Impact level of a defect on the system

## T

- Test Case: Detailed steps and expected results
- Test Data: Data used to execute test cases
- Test Environment: Hardware, software, and configuration used for testing
- Test Plan: Scope and approach for a testing effort
- Test Strategy: Long-term testing approach and principles
- Test Suite: A collection of related test cases

## U

- UAT: User acceptance testing to confirm business readiness
- Usability Testing: Evaluating ease of use and user experience
